Учебная операционная система MyOS

1. Описание проекта

MyOS — это учебная операционная система, которую я буду делать на Python. Конечно, это не полноценная ОС как Windows или Linux, а программа, которая показывает основные принципы их работы.

В проекте будут пользователи, процессы, работа с памятью и файлами. Данные будут храниться в базе SQLite. Управлять системой можно будет через команды в консоли.

2. Границы системы

Что будет реализовано

Пользователи. Будет обычный пользователь и администратор с разными правами.

Процессы. Можно будет создавать процессы, смотреть их список и завершать их.

Память. Будет сделана простая имитация выделения памяти для процессов.

Файлы. Пользователь сможет создавать и читать файлы. Информация о них будет храниться в SQLite.

Системные вызовы. Основные действия системы будут выполняться через функции системных вызовов.

Командная строка. Через неё пользователь сможет вводить команды и работать с системой.

Логи. Основные действия и системные вызовы будут записываться в журнал

3. Сценарии использования

В MyOS будет несколько основных действий, которые сможет выполнять пользователь или сама система.

1. Вход в систему

Пользователь вводит свой логин и пароль. Система проверяет данные в базе. Если всё правильно, пользователь входит в систему.

Роль: пользователь или администратор
Системный вызов: sys_login
Модули: shell.py, syscalls.py, db.py

2. Создание файла

Пользователь вводит команду для создания файла. Система проверяет его права и после этого создаёт файл.

Роль: пользователь
Системный вызов: sys_create
Модули: shell.py, syscalls.py, db.py

3. Чтение файла

Пользователь выбирает файл, который хочет открыть. Система проверяет наличие файла и доступ к нему, после чего показывает его содержимое.

Роль: пользователь
Системные вызовы: sys_open, sys_read
Модули: shell.py, syscalls.py, db.py

4. Запуск процесса

Пользователь запускает процесс через команду. Система создаёт его, выделяет нужную память и добавляет в список процессов.

Роль: пользователь
Системный вызов: sys_exec
Модули: shell.py, syscalls.py, kernel.py, db.py

5. Просмотр процессов

Пользователь может посмотреть, какие процессы сейчас есть в системе. Для этого MyOS получает список процессов из базы и показывает его в консоли.

Роль: пользователь или администратор
Системный вызов: sys_ps
Модули: shell.py, syscalls.py, db.py

6. Завершение процесса

Пользователь выбирает нужный процесс и завершает его. После этого система освобождает память, которую он использовал.

Роль: пользователь или администратор
Системный вызов: sys_kill
Модули: shell.py, syscalls.py, kernel.py, db.py

7. Работа с памятью

При запуске процесса система выделяет ему определённое количество памяти. Если памяти не хватает, система сообщает об ошибке.

Роль: система
Системный вызов: sys_alloc
Модули: kernel.py, syscalls.py

8. Просмотр журнала

Администратор может посмотреть журнал действий системы. В нём будут храниться выполненные системные вызовы и их результаты.

Роль: администратор
Системный вызов: sys_log
Модули: shell.py, syscalls.py, db.py

4. Нефункциональные требования

Кроме основных функций, для MyOS есть несколько требований к её работе.

Производительность

Один системный вызов должен выполняться не дольше 50 мс.

Система должна поддерживать работу минимум 10 процессов одновременно.

Команды пользователя должны выполняться без долгих задержек.

Проверить скорость работы можно с помощью perf_counter в Python.

Надёжность

Если в одном процессе произойдёт ошибка, вся система не должна завершать работу.

При ошибке информация о ней должна записываться в журнал.

Если процесс пытается использовать слишком много памяти, система должна остановить операцию и вывести ошибку.

Безопасность

Пароли пользователей будут храниться в виде хэша SHA-256.

Обычный пользователь не сможет изменять файлы администратора.

Все системные вызовы будут записываться в журнал.

Поддерживаемость

Код проекта будет разделён на отдельные файлы и модули.

Каждый модуль будет отвечать за свою часть системы.

Желательно, чтобы один модуль был не больше 300 строк, чтобы код было проще читать и изменять.

Требования к ресурсам

Для запуска MyOS нужен Python версии 3.10 или выше.

Для базы данных будет использоваться SQLite, поэтому отдельный сервер базы данных не нужен.

Система должна запускаться на обычном компьютере без специального оборудования.

5. Анализ рисков

Во время разработки MyOS могут возникнуть разные проблемы. Лучше учитывать их заранее, чтобы потом было проще с ними разобраться.

1. Нехватка времени

Можно не успеть сделать все запланированные функции.

Решение: сначала сделать самые важные части проекта: ядро, базу данных, работу с файлами и командную строку. Дополнительные функции делать уже после этого.

2. Проблемы с SQLite

При одновременной работе нескольких процессов могут возникнуть ошибки или блокировка базы данных.

Решение: использовать одно подключение к базе и выполнять запросы по очереди.

3. Ошибки в системных вызовах

При большом количестве системных вызовов будет сложнее понять, где именно появилась ошибка.

Решение: записывать системные вызовы и их результаты в журнал.

4. Необработанные ошибки

В коде можно забыть обработать какую-нибудь ошибку, из-за чего программа может завершиться.

Решение: проверять обработку ошибок в каждом основном модуле и использовать обработку исключений.

5. Сложность проекта

По мере разработки файлов и функций станет больше, поэтому можно начать путаться в коде.

Решение: разделять программу на отдельные модули и вести документацию по проекту.

6. Ошибки при работе с памятью

Процесс может попытаться получить больше памяти, чем ему разрешено.

Решение: установить ограничение памяти и проверять его перед выделением памяти процессу.

6. Созданный прототип

На данный момент сделан базовый прототип MyOS на Python.

В проекте есть база данных SQLite, в которой созданы таблицы для пользователей, процессов, файлов и журнала системных вызовов.

Также сделана простая командная оболочка. Через неё можно вводить команды и получать результат.

Сейчас работают следующие команды:

help — показывает список команд;

echo — выводит введённый текст;

users — показывает пользователей;

exit — завершает работу программы.

Системные вызовы sys_echo и sys_get_users записываются в таблицу syscalls_log. Благодаря этому можно посмотреть, какие действия выполнялись в системе.

Для проверки проекта нужно запустить shell.py, выполнить несколько команд и после этого проверить журнал в базе данных.

7. Словарь терминов

Операционная система — система, которая управляет работой компьютера и его ресурсами.

Ядро — основная часть операционной системы, которая отвечает за выполнение основных операций.

Процесс — программа, которая в данный момент выполняется системой.

Память — ресурс компьютера, который используется программами во время работы.

Файловая система — способ хранения и организации файлов.

Системный вызов — обращение программы к функциям операционной системы.

Пользователь — человек, который работает с системой и имеет определённые права.

Администратор — пользователь с расширенными правами управления системой.

Командная оболочка — программа, через которую пользователь вводит команды.

SQLite — небольшая база данных, которая хранится в одном файле.

Лог — запись информации о действиях и событиях, которые происходили в системе.

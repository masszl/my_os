## 1. Цель работы

Целью учебной практики являлась разработка учебной модели операционной системы StudyOS на языке Python.

В ходе работы необходимо было реализовать основные программные модули, организовать их взаимодействие, подключить базу данных и провести тестирование.

## 2. Используемые технологии

Для разработки проекта использовались:

- Python — основной язык программирования.
- SQLite — хранение данных пользователей, файлов, процессов и системных вызовов.
- Visual Studio Code — среда разработки.
- Git — контроль версий.
- GitHub — хранение исходного кода проекта.

## 3. Разработка проекта

### 3.1. Проектирование

На первом этапе были определены основные функции системы, разработана архитектура и составлены требования к программным модулям.

Проект был разделён на несколько компонентов, каждый из которых отвечает за отдельную часть работы системы.

### 3.2. Реализация программных модулей

В ходе практики были разработаны следующие модули:

| Модуль | Назначение |
|---|---|
| db.py | Работа с базой данных SQLite |
| auth.py | Авторизация и проверка прав пользователей |
| fs.py | Создание, чтение и удаление файлов |
| kernel.py | Управление памятью и состоянием системы |
| scheduler.py | Управление процессами |
| syscalls.py | Обработка системных вызовов |
| shell.py | Командная оболочка пользователя |

Всего в проекте реализовано семь основных модулей.

### 3.3. База данных

Для хранения информации используется SQLite.

База данных содержит пять основных таблиц:

1. users — учётные записи пользователей.
2. processes — информация о процессах.
3. files — файлы виртуальной системы.
4. syscalls_log — журнал системных вызовов.
5. memory_state — состояние оперативной памяти.

### 3.4. Командная оболочка

Была реализована командная оболочка, позволяющая пользователю взаимодействовать с системой.

Основные команды: help, login, logout, whoami, create, cat, ls, delete, run, ps, kill, mem, logs, exit.

Командная оболочка передаёт запросы соответствующим модулям и выводит результаты выполнения операций.

### 3.5. Разграничение прав доступа

В системе предусмотрены роли администратора и обычного пользователя.

Администратор имеет расширенные права управления системой. Для обычного пользователя действуют ограничения на отдельные операции, например завершение процессов и удаление чужих файлов.

## 4. Тестирование

В процессе разработки проводилось тестирование отдельных модулей и их совместной работы.

Были подготовлены:

- Модульные тесты.
- Функциональные тесты.
- Интеграционные сценарии.
- Нагрузочные тесты.
- Регрессионные проверки.

Проверялись работа с базой данных, авторизация, файловые операции, управление процессами, использование памяти и обработка системных вызовов.

На одном из подтверждённых запусков семь тестовых файлов завершились без ошибок. Окончательные результаты нагрузочных и регрессионных проверок необходимо подтвердить повторным запуском.

## 5. Возникшие трудности

Во время разработки возникали ошибки импорта модулей, проблемы со структурой таблиц SQLite и управлением памятью процессов.

Для устранения ошибок проверялись связи между модулями, корректировались SQL-запросы и дорабатывались функции управления процессами.

Отдельное внимание уделялось освобождению памяти после завершения процесса.

## 6. Результаты работы

В результате учебной практики разработана рабочая учебная модель операционной системы StudyOS.

Реализованы командная оболочка, работа с пользователями, файловые операции, управление процессами и памятью, а также журналирование системных вызовов.

Созданы тесты и техническая документация.

При этом проект остаётся учебной симуляцией: файловая система не поддерживает полноценную иерархию каталогов, а некоторые расширенные возможности из методических материалов не реализованы.

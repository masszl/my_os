 Системные сценарии StudyOS

 SS-01: Первый запуск ОС

**Предусловие:** база данных отсутствует, все модули системы готовы к работе.

**Шаги:**
1. Сделать резервную копию существующей базы данных.
2. Проверить создание новой базы через db.py.
3. Убедиться, что файл базы данных создан.
4. Проверить наличие таблиц users, processes, files, syscalls_log, memory_state.
5. Проверить возможность дальнейшей работы системы.

**Ожидаемый результат:** база данных создаётся, необходимые таблицы присутствуют, система готова к работе.

**Статус:** Не проверен.

 SS-02: Работа администратора

**Предусловие:** пользователь admin зарегистрирован с ролью admin.

**Шаги:**
1. Запустить оболочку StudyOS.
2. Войти под пользователем admin.
3. Создать файл /ss02_a.txt с текстом first file.
4. Создать файл /ss02_b.txt с текстом second file.
5. Прочитать файл /ss02_a.txt.
6. Запустить процессы app1 и app2.
7. Посмотреть список процессов.
8. Завершить процесс app1.
9. Проверить использование памяти.
10. Выйти из системы.

**Ожидаемый результат:** все разрешённые команды выполняются, файлы сохраняются, процессы запускаются и завершаются, системные вызовы записываются в журнал.

**Статус:** Не проверен.

 SS-03: Работа обычного пользователя

**Предусловие:** пользователь user зарегистрирован с ролью user, файл /ss02_a.txt принадлежит admin.

**Шаги:**
1. Запустить оболочку StudyOS.
2. Войти под пользователем user.
3. Создать собственный файл /ss03_my.txt.
4. Попытаться удалить файл администратора /ss02_a.txt.
5. Запустить процесс user_app.
6. Попытаться завершить процесс через команду kill.
7. Проверить журнал системных вызовов.
8. Выйти из системы.

**Ожидаемый результат:** создание собственного файла и запуск процесса разрешены. Удаление чужого файла и команда kill запрещены. Отказы записываются в журнал со статусом DENIED.

**Статус:** Не проверен.

 SS-04: Восстановление после ошибок

**Предусловие:** система работает, пользователь admin зарегистрирован.

**Шаги:**
1. Запустить оболочку.
2. Попытаться войти с неправильным паролем.
3. Войти с правильным паролем.
4. Попытаться прочитать несуществующий файл.
5. Попытаться завершить процесс с PID 99999.
6. Попытаться создать файл с уже существующим путём.
7. Проверить, что оболочка продолжает принимать команды.
8. Завершить работу.

**Ожидаемый результат:** система корректно обрабатывает ошибки, не завершает работу аварийно и продолжает принимать команды.

**Статус:** Не проверен.

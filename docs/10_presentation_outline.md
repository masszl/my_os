**StudyOS — учебная операционная система**

Разработка учебной модели операционной системы на Python.

## Слайд 2. Цель проекта

Цель работы — разработать учебную модель операционной системы.

Основные задачи:
- Реализовать командную оболочку.
- Создать систему пользователей.
- Добавить работу с файлами.
- Реализовать управление процессами и памятью.
- Провести тестирование.

## Слайд 3. Используемые технологии

- Python — разработка программных модулей.
- SQLite — хранение информации.
- Visual Studio Code — написание и отладка кода.
- Git и GitHub — контроль версий.

## Слайд 4. Архитектура StudyOS

Система состоит из семи модулей:

- shell.py — командная оболочка.
- syscalls.py — системные вызовы.
- kernel.py — управление памятью.
- scheduler.py — управление процессами.
- fs.py — файловая система.
- auth.py — авторизация.
- db.py — работа с базой данных.

Модули взаимодействуют друг с другом для выполнения команд пользователя.

## Слайд 5. База данных

В проекте используется SQLite.

Созданы пять таблиц:

- users — пользователи.
- processes — процессы.
- files — файлы.
- syscalls_log — журнал операций.
- memory_state — состояние памяти.

База данных позволяет сохранять состояние отдельных компонентов системы.

## Слайд 6. Командная оболочка

Для управления системой создана текстовая оболочка.

Примеры команд:

- login — вход пользователя.
- create — создание файла.
- cat — чтение файла.
- run — запуск процесса.
- ps — просмотр процессов.
- kill — завершение процесса.
- logs — просмотр журнала.

## Слайд 7. Пользователи и права доступа

В StudyOS предусмотрены две роли:

- Администратор.
- Обычный пользователь.

Администратор имеет расширенные права.

Для обычного пользователя предусмотрены ограничения на выполнение отдельных операций.

## Слайд 8. Управление процессами и памятью

В системе реализованы:

- Создание процессов.
- Просмотр списка процессов.
- Завершение процессов.
- Выделение оперативной памяти.
- Освобождение памяти.
- Контроль лимита памяти.

## Слайд 9. Тестирование

Проводились:

В ходе разработки обнаруживались и исправлялись ошибки импорта, работы с базой данных и освобождения памяти.
